## Named imports

Each icon has a PascalCase component name ending in `Icon`.

```tsx
import { HomeIcon, ShopIcon, CashRegisterIcon } from "solite-icons";

export function Toolbar() {
  return (
    <nav aria-label="Main navigation">
      <a href="/">
        <HomeIcon size={20} /> Home
      </a>
      <a href="/shops">
        <ShopIcon size={20} /> Shops
      </a>
      <a href="/pos">
        <CashRegisterIcon size={20} /> Register
      </a>
    </nav>
  );
}
```

Named imports let your production bundler remove unused icons. A direct module import is also available:

```tsx
import ShopIcon from "solite-icons/icons/shop";
```

For a name stored in data or configuration, choose the separate [eager or lazy renderer](/dynamic). Named imports remain the preferred option for a name known in source.

## Component props

| Prop                 | Default        | Purpose                                    |
| -------------------- | -------------- | ------------------------------------------ |
| `size`               | `24`           | Width and height as a number or CSS length |
| `color`              | `currentColor` | Stroke color                               |
| `strokeWidth`        | `1.75`         | Outline thickness                          |
| `nonScalingStroke`   | `false`        | Keep stroke thickness when scaling the SVG |
| `className`, `style` | none           | CSS styling                                |
| `title`              | none           | Accessible title with a unique ID          |
| `ref`                | none           | Reference to the root SVG                  |

Standard SVG props and `aria-*` / `data-*` attributes are forwarded. Explicit `width` and `height` props override `size`.

## Visual defaults with a provider

```tsx
import { HomeIcon, SearchIcon, SoliteProvider } from "solite-icons";

export function ToolbarIcons() {
  return (
    <SoliteProvider size={20} strokeWidth={1.75} className="toolbar-icon">
      <HomeIcon />
      <SoliteProvider size={16} nonScalingStroke className="compact-icon">
        <SearchIcon size={18} className="search-icon" />
      </SoliteProvider>
    </SoliteProvider>
  );
}
```

Provider defaults are limited to `size`, `color`, `strokeWidth`, `nonScalingStroke`, and `className`. Nested providers inherit unspecified values; each icon's explicit props override defaults. Here the search icon renders at 18px and receives `toolbar-icon compact-icon search-icon`. Classes append in that order, without utility-class deduplication.

Provider defaults do not include titles, ARIA names, refs, or interaction handlers. Supply those on the individual icon or control. Without a provider, icons keep the defaults in the table above. See [styling](/styling) for non-scaling strokes and global CSS.

## An icon-only button

Name the button so people using assistive technology can understand its action.

```tsx
import { SettingsIcon } from "solite-icons";

<button type="button" aria-label="Open settings">
  <SettingsIcon size={20} />
</button>;
```

Icons are decorative by default. The button supplies the accessible name. Read the [accessibility guide](/accessibility) before using an icon as the only source of information.

## Refs and reusable props

```tsx
import { useRef } from "react";
import { ShopIcon, type SoliteIconProps } from "solite-icons";

export function ShopMark(props: SoliteIconProps) {
  const ref = useRef<SVGSVGElement>(null);
  return <ShopIcon {...props} ref={ref} />;
}
```

For a component slot, use the TypeScript-only `SoliteIconComponent` type:

```tsx
import { HomeIcon, type SoliteIconComponent } from "solite-icons";

type NavigationItem = {
  label: string;
  href: string;
  icon: SoliteIconComponent;
};

const item: NavigationItem = { label: "Home", href: "/", icon: HomeIcon };
```

The type describes a component that accepts `SoliteIconProps` and a forwarded `SVGSVGElement` ref. It adds no runtime component.

## Server rendering and Next.js

Icons support server-rendered HTML. The published React modules preserve their `"use client"` boundary for Next.js. Import the components normally; add your own client boundary when your containing component uses hooks or event handlers.

Named and eager icons render synchronously. The candidate lazy entry suspends while its module loads; see [SSR and bundling limits](/dynamic#ssr-and-bundling-limits) before using it for server-rendered content.

## CommonJS

```js
const { ShopIcon } = require("solite-icons");
const { SoliteIcon } = require("solite-icons/dynamic");
```

Separate ESM and CommonJS type declarations are included.
