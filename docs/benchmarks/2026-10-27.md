# Bundle benchmark: 27 October 2026

This is a snapshot of the published npm packages listed below. The [PNG chart](../../assets/benchmark-2026-10-27.png) uses only the measurements in the accompanying [JSON data](2026-10-27.json).

## Browser JavaScript

Values are KiB, where 1 KiB is 1,024 bytes. Each value is the complete minified icon-only JavaScript output compressed with gzip level 9. React is excluded.

| Package          | Version | 1 icon | 10 icons | 50 icons |
| ---------------- | ------- | -----: | -------: | -------: |
| solite-icons     | 0.2.1   |   0.63 |     1.10 |     2.87 |
| lucide-react     | 1.62.0  |   1.91 |     2.58 |     5.97 |
| @heroicons/react | 2.2.0   |   0.44 |     1.63 |     6.07 |
| react-icons      | 5.7.0   |   1.21 |     1.71 |     3.39 |

The first scenario imports the Home icon, called House in Lucide. The other scenarios use the first 10 and 50 corresponding icon purposes from each library's `exports` array in the JSON snapshot. The drawings and component features differ. Heroicons uses its 24px outline entry; React Icons uses its Feather entry.

## Build method

- Node v22.23.4, esbuild 0.28.1, React 19.2.8.
- Verified the published tarballs against their SHA-512 integrity values. Exact tarball URLs and integrity strings are recorded in the JSON.
- Installed/extracted the pinned packages into an isolated directory, outside the library source.
- Built each scenario with esbuild using `bundle: true`, `minify: true`, `treeShaking: true`, `format: "esm"`, `platform: "browser"`, and `target: "es2020"`.
- Excluded `react` and `react/*` in every build.
- Used a global assignment to retain every selected import, then measured the full output with Node's `gzipSync(output, { level: 9 })`.

Example entry for the one-icon Solite scenario:

```js
import { HomeIcon } from "solite-icons";
globalThis.__iconBenchmark = [HomeIcon];
```

For larger scenarios, import the selected names from the package entry recorded in the JSON and retain all of them in the same array. The generated sink is part of the measured output. Solite's one-icon metafile confirmed that only `home.js` and shared helpers contributed bytes; none of the other 252 glyph modules contributed.

## Full package footprint

This is the sum of file sizes inside each published npm tarball. It is logical unpacked size, not filesystem block allocation, and excludes React and other peer packages.

| Package          | Download KiB | Unpacked MiB |
| ---------------- | -----------: | -----------: |
| solite-icons     |       261.36 |         1.33 |
| lucide-react     |      3114.63 |        34.75 |
| @heroicons/react |       279.35 |         3.52 |
| react-icons      |     22233.01 |        84.19 |

1 MiB is 1,048,576 bytes. Packages contain different numbers of icons, variants, and families. This is an installation footprint comparison, not an equal-sized collection comparison, and it is not the amount sent to a browser.

## Scope

These measurements describe these exact versions and scenarios. They do not measure real page loading, browser FPS, hydration, mobile performance, or internet download latency. The chart does not claim that one library is always faster. Results can change with library versions, imports, bundlers, and application code.

The chart omits local installation and render timing microbenchmarks because those depend strongly on the machine and are not necessary to compare payload sizes.
