# Application symbol coverage proposal

Status: design only, pending approval with the parent expansion design. This document proposes exactly 100 new canonical names. It does not add icon definitions or exports.

The proposal follows the existing 24 by 24 outline grid, 1.75 default stroke, rounded caps and joins, currentColor, and no fill. Every drawing must use original editable geometry. Concepts describe silhouettes and essential details, not copied paths.

The allocation is 14 media playback, 13 connectivity and devices, 4 security, 9 education, 13 transport, 17 weather and nature, 13 health, and 17 everyday application symbols. Existing equivalents belong in search metadata. General interface controls, accessibility settings, text editing, document tools, and developer infrastructure belong to the other batches.

## Reuse decisions and drawing review

The existing `book` already depicts an open book, so `book-open` is an alias. Existing `volume` and `headphones` cover sound and headset requests; the proposed `speaker` specifically depicts a physical speaker cabinet for output selection. Existing `clock` covers time; `watch` depicts a wrist-worn device for pairing. Existing `shield`, `shield-check`, `shield-lock`, `key`, `lock`, `unlock`, `fingerprint`, `eye`, and `eye-off` cover the usual access and privacy concepts without additional badge variants. Existing `activity` covers pulse and vital-sign requests, so there is no counted heart-and-pulse composite.

Use `stop-circle` as the playback control and add `stop` as its search alias. This keeps it distinct from the other batch's general `square`. A plain record circle is omitted because the interface batch owns `circle` and `circle-dot`. `disc` needs visible groove details to remain distinct from those geometric primitives.

The largest optical risks are `film`, `cassette`, `gamepad`, `remote-control`, `sim-card`, `microscope`, `traffic-light`, `snowflake`, `dna`, and `cake`. At 16 pixels, remove optional details before narrowing gaps or thinning the family stroke. `cloud-snow` describes falling snow; `snowflake` describes cold or winter. `cloud-lightning` describes weather; `flame` describes fire or heat. `fuel` and `charging-station` must keep distinct nozzle and cable silhouettes. These use cases justify their separate symbols.

No proposed name collides with the 253 canonical names in the current `src/definitions` baseline. Implementation still needs review against the other two approved name lists, followed by contact-sheet review at 16, 20, and 24 pixels. Approval of names does not establish drawing quality.
